Connection help

The chooser lists only this prototype’s USB identity. An empty list means the browser cannot see an eligible device; it is not proof that the Pi failed to boot.

  • Use the Pi socket marked USB, not PWR IN, and a known data cable.
  • Open this page directly in desktop Chrome or Edge on the computer physically connected to the Pi.
  • Linux in a virtual machine, remote session or Chromebook container may see different USB devices from the browser. Check device forwarding on the actual host.

In the connected Linux computer’s terminal:

lsusb -d 1d6b:0104
ls -l /dev/ttyACM*

No matching USB device: check cable, socket and host USB access first. A matching device but no ttyACM port: check the host CDC ACM driver. An existing port that cannot open: close other serial apps and check its group permissions.

If the port belongs to dialout, adding your user to that group grants serial-device access. On distributions using that group:

sudo usermod -aG dialout "$USER"

Log out and back in after a group change. Sandboxed browsers can require additional device permission. Do not run the browser as root or make the port world-writable.

New images write satooshi-usb-status.txt to the SD card’s boot partition. It reports USB startup only, never seed words, PINs or wallet addresses. Read it with the Pi disconnected from power; do not reflash a funded device without its paper backup.

A Trezor uses a different USB interface and is not expected in this serial chooser. The shared prototype USB IDs are a discovery filter, not proof of authenticity.

On the device

  • ◀Tap: previous. Hold: cancel.
  • ▶Tap: next. Hold: select / confirm.

Hold for about one second, then release. Older 0.1 firmware uses both buttons to confirm. Up to five PIN attempts. Recovery words appear on the device only — write them on paper, never here.

Reset device

Deletes the wallet key from the device. Without your written 24 words, funds are lost. The device asks for two separate physical confirmations.
